# Contract gaps

Fields the web app needs that the contracts (`packages/contracts`) lack or under-constrain. Reconciled against the
merged backend (`apps/api`, `apps/worker`) in Task 16; each row states what the backend does today. Each gap is derived
client-side or guarded in the web app until the contracts catch up (additive changes only).

| Route                                                                                                                                      | Field                      | Why                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/connections/:provider/install` (`connections.install`)                                                                          | `InstallResponse.url`      | Typed `z.string()`; should be a constrained absolute URL. Backend: GitHub returns its https install page; the fake provider returns `${PUBLIC_ORIGIN}/api/connections/fake/callback?state=…`, which is `http://` in local dev. The app navigates with `window.location.assign`, so it re-checks the URL (`features/setup/location.ts` `safeInstallUrl`: https only, http also in mock/development) and refuses anything else.                                                                                 |
| `POST /api/connections/:provider/install` (`connections.install`)                                                                          | enabled providers          | No route lists the providers the API has enabled. The setup's Connect button always installs `github`, which is a 400 ("Provider github is not enabled") on a local stack with only the fake provider; the fake connection has to be installed over the API (`POST /api/connections/fake/install`, then open the returned URL), as `e2e/local/run.spec.ts` does. Needs e.g. `GET /api/connections/providers`.                                                                                                 |
| `GET/PUT /api/projects/:projectId/agent` (`agents.get`, `agents.put`)                                                                      | idle end timeout           | The Agent & settings board has an editable "End idle runs after" limit, but no contract field carries it. Backend: fixed `IDLE_END_SECONDS = 600` (`packages/core`), passed to the run workflow as `idleEndSeconds`; not per agent. The app shows 10 read-only (`features/desk/agent.form.ts` `IDLE_END_MINUTES`, DeskAgent `idleReadOnly`) and a limits save never sends it.                                                                                                                                 |
| `GET /api/projects/:projectId` (`projects.get`, `ProjectDto`)                                                                              | repository web URL         | No provider-agnostic web URL for the repo (backend has none either). The app builds `https://github.com/<repoPath>` (`features/runs/map.ts` `repoUrlOf`, and the screens' "Repo on GitHub" link), which is wrong for the fake provider's `dev/demo`. The provider-specific board copy ("Repo on GitHub", "No webhooks from GitHub", NeedsYou's GitHub card) predates this and stays.                                                                                                                          |
| `GET /api/projects/:projectId/ignored` (`projects.ignored`, `IgnoredEventDto`)                                                             | ticket / comment URL, kind | Only `ticketRef` (the provider-local number, e.g. `160`) and `ticketKind`, which the backend always sends as `null` (inbound_events does not store it). The "Comment" link is built as `<repo URL>/issues/<n>` (GitHub paths, `toIgnored`; `pull` only when the kind is known) and opens the ticket, not the comment. Needs `ticketUrl`, `ticketKind` and ideally `commentUrl`.                                                                                                                               |
| `GET /api/projects/:projectId/runs` (`runs.list`)                                                                                          | aggregate counts           | Pages only (`limit` ≤ 100, `nextCursor`); `ProjectDto.counts` has needsYou/running/queued but no ended or total. The app follows the cursor for up to 10 pages (1000 runs, `features/runs/queries.ts`) for the Ended/All counts, runs per ticket and the list. Beyond that the list and those counts are capped silently (`truncated` is tracked but not shown, to avoid new copy). Needs per-filter counts (and runs-per-ticket) from the server.                                                            |
| `GET /api/runs/:runId/log` (`runs.log`), SSE `event: event` on `/api/runs/:runId/events` (`RunEventDto`)                                   | `payload` shape per `type` | `payload` is `z.record(z.string(), z.unknown())`. Backend (worker) writes: `lifecycle` `{ line, kind, text }`, `scrollback` `{ line, text, truncated }`, `status` `{ status, exitCode, failureReason }`, `comment` `{ kind, commentId }`. The app reads `{ text }` for `lifecycle` and `scrollback` and `{ status }` for `status` (`features/runs/detail.map.ts`, parsed with `safeParse`, anything else skipped), which matches. Needs a discriminated union on `type` in the schema.                        |
| SSE `event: status` on `/api/runs/:runId/events` (`RunStatusEvent`), `event: run` on `/api/projects/:projectId/events` (`ProjectRunEvent`) | status change time         | No timestamp on either frame. Backend: every status change also appends a `status` run event whose `ts` is the transition time, so the run stream carries it as an `event: event` frame; the project stream has nothing. The app approximates `startedAt` / `idleSince` / `finishedAt` from the browser clock when a status frame arrives (`features/runs/applyEvents.ts`) until the run detail is refetched, so live elapsed and idle times can be off by the stream delay. Needs `at` (ISO) on both frames. |
| `GET /api/projects/:projectId/skills` (`SkillDto.lastCommit`)                                                                              | `lastCommit.message`       | The backend fills `{ sha, message, at }` (the fake provider: `Update <name>`), but the DeskSkills screen shows only `<sha7>, <relative>` (`features/desk/map.ts`), so the message is dropped. Showing it needs design sign-off (not a contract change).                                                                                                                                                                                                                                                       |

Resolved in Task 16 (rows removed): the command format (stored without `/`; an ignored first line that is no command is
kept as typed and shown as is), `user.handle` (a better-auth additional field the API always sets), `Last-Event-ID` /
`after` (event frames have `id: <seq>`, status frames none; the `after` query wins over the header), `seq` semantics (one
per-run sequence: each status change is a run event, the project stream sends its seq), the ticket ref format (the
provider-local number, `?ticket=12`) and the counts semantics (`running` counts starting, running and idle runs).
