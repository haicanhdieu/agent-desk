# Contract gaps

Fields the web app needs that the contracts (`packages/contracts`) lack or under-constrain. Resolved in Task 16 after
the backend merges. Each gap is derived client-side or guarded in the web app until then.

| Route                                                                                                                                      | Field                      | Why                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/connections/:provider/install` (`connections.install`)                                                                          | `InstallResponse.url`      | Typed `z.string()`; should be a constrained absolute URL (`z.url()` with protocol `https`). The app navigates to it with `window.location.assign`, so it re-checks it (`features/setup/location.ts` `safeInstallUrl`: https only, http also in mock/development) and refuses anything else.                                                                                                                                                                                        |
| `GET/PUT /api/projects/:projectId/agent` (`agents.get`, `agents.put`)                                                                      | idle end timeout           | The Agent & settings board has an editable "End idle runs after" limit, but no contract field carries it (the worker fixes it at 10 min, control-plane spec §5). The app shows 10 read-only (`features/desk/agent.form.ts` `IDLE_END_MINUTES`, DeskAgent `idleReadOnly`) and a limits save never sends it.                                                                                                                                                                         |
| `GET /api/projects/:projectId` (`projects.get`, `ProjectDto`)                                                                              | repository web URL         | No provider-agnostic web URL for the repo. The app builds `https://github.com/<repoPath>` (`features/runs/map.ts` `repoUrlOf`, and the screens' "Repo on GitHub" link). The provider-specific board copy ("Repo on GitHub", "No webhooks from GitHub", NeedsYou's GitHub card) predates this and stays.                                                                                                                                                                            |
| `GET /api/projects/:projectId/ignored` (`projects.ignored`, `IgnoredEventDto`)                                                             | ticket / comment URL       | Only `ticketRef` and `ticketKind`. The "Comment" link is built as `<repo URL>/issues/<n>` or `/pull/<n>` (GitHub paths, `toIgnored`) and opens the ticket, not the comment. Needs `ticketUrl` and ideally `commentUrl`.                                                                                                                                                                                                                                                            |
| `GET /api/projects/:projectId/runs` (`runs.list`)                                                                                          | aggregate counts           | Pages only (`limit` ≤ 100, `nextCursor`); `ProjectDto.counts` has needsYou/running/queued but no ended or total. The app follows the cursor for up to 10 pages (1000 runs, `features/runs/queries.ts`) for the Ended/All counts, runs per ticket and the list. Beyond that the list and those counts are capped silently (`truncated` is tracked but not shown, to avoid new copy). Needs per-filter counts (and runs-per-ticket) from the server.                                 |
| `GET /api/runs/:runId/log` (`runs.log`), SSE `event: event` on `/api/runs/:runId/events` (`RunEventDto`)                                   | `payload` shape per `type` | `payload` is `z.record(z.string(), z.unknown())`. The app reads `{ text: string }` for `lifecycle` and `scrollback` and `{ status: string }` for `status` (`features/runs/detail.map.ts` `TextPayload` / `StatusPayload`, parsed with `safeParse`, anything else skipped); `comment` is not read. Needs a discriminated union on `type`.                                                                                                                                           |
| SSE `event: status` on `/api/runs/:runId/events` (`RunStatusEvent`), `event: run` on `/api/projects/:projectId/events` (`ProjectRunEvent`) | status change time         | No timestamp. The app approximates `startedAt` / `idleSince` / `finishedAt` from the browser clock when a status event arrives (`features/runs/applyEvents.ts`) until the run detail is refetched, so live elapsed and idle times can be off by the stream delay. Needs `at` (ISO) on both.                                                                                                                                                                                        |
| `RunDto.command`, `IgnoredEventDto.command` (`runs.*`, `projects.ignored`)                                                                 | command format             | `z.string()` with no stated normalization. The mock stores it without the leading `/` (like `RuleDto.command`, a `SlugName`), and the UI adds `/` (`features/runs/map.ts`, `detail.map.ts`; a null ignored command shows `—`). If the backend stores `/code-build`, the UI would show `//code-build`. Confirm the backend format and state it in the schema.                                                                                                                       |
| `GET /auth/get-session` (better-auth user)                                                                                                 | `user.handle`              | Mocked as an additional user field (GitHub login). `features/auth/session.ts` requires it (`handle: z.string()`): if the real user lacks it, the session parse fails and the root guard's `ensureQueryData(sessionQuery)` errors (root error boundary, not sign-in). It feeds the top-bar login and initials. `/o/<slug>` routing uses the organization `slug`, not `handle`. The API must declare `handle` in `user.additionalFields`, or the app needs a fallback (e.g. `name`). |
| `GET /api/projects/:projectId/skills` (`SkillDto.lastCommit`)                                                                              | `lastCommit.message`       | The contract has `{ sha, message, at }`, but the DeskSkills screen shows only `<sha7>, <relative>` (`features/desk/map.ts`), so the message is dropped. Showing it needs design sign-off (it is not a contract change).                                                                                                                                                                                                                                                            |
| SSE `/api/runs/:runId/events`                                                                                                              | `Last-Event-ID` / `after`  | Assumed: each message's `id` is its `seq`, and the server honors both the `after` query and the `Last-Event-ID` header on reconnect, replaying events with `seq` greater than it (`features/runs/useRunEvents.ts`; the mock does). Not stated in the contract.                                                                                                                                                                                                                     |
| SSE run and project streams (`RunStatusEvent.seq`, `ProjectRunEvent.seq`)                                                                  | `seq` semantics            | Assumed: every status change gets a distinct, increasing `seq`, shared by the run stream and the project stream, so the client orders status updates by `seq` and drops stale ones. Not stated in the contract.                                                                                                                                                                                                                                                                    |
| `GET /api/projects/:projectId/runs?ticket=` (`RunListQuery.ticket`)                                                                        | ticket ref format          | `z.string()`. The app sends the full ref `owner/repo#n` (`ticketRef` in `app/routes/o.$org.p.$project.runs.index.tsx`); the mock matches it exactly. Confirm the format (provider-agnostic ref) with the backend.                                                                                                                                                                                                                                                                  |
| `GET /api/projects`, `GET /api/projects/:projectId` (`ProjectDto.counts`)                                                                  | counts semantics           | Assumed (mock): `needsYou` = idle runs, `running` = starting + running (excludes idle), `queued` = queued. The Runs chips and the top-bar badge rely on this. Not stated in the contract.                                                                                                                                                                                                                                                                                          |
