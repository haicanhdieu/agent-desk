# Severity

Every finding gets exactly one severity. Pick the highest row whose description fits. When torn between two, pick the higher one and say why in `why`.

| Severity     | Means                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Checklist label | Fixed before merge |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------- | ------------------ |
| **critical** | Security or tenancy hole (missing authz, unscoped query, bypassed `withOrg`/RLS, secret in code/logs/DB/events, untrusted text into shell/SQL/k8s spec/HTML, unverified webhook). Wrong architecture (layering broken, app imports app, types duplicated outside `packages/contracts`, provider names outside adapters, non-deterministic workflow code, k8s/secrets/providers called around their seam, edited applied migration). Data loss. Damaging performance (unbounded query or list on a hot path, N+1 per request, leak of sockets/streams/watches, blocking the event loop). Breaks the build or the API contract. | blocker         | yes                |
| **high**     | Wrong behavior against the issue or spec, including its failure cases. New behavior or fixed bug with no test that fails without it. A **MUST** in `docs/conventions/` broken (not already critical). Unhandled error, floating promise, race between api and worker, missing idempotency on webhook/poll/activity code. A performance problem that bites at modest scale (missing index for a new query, re-render storm, unpaginated list that will grow).                                                                                                                                                                  | blocker         | yes                |
| **medium**   | A **SHOULD** in `docs/conventions/` broken. Missing edge case (empty, duplicate, very large, out of order). UI missing a loading, empty or error state or a story. Weak error message or log (no context, wrong level). Design that will cost maintenance: unclear responsibility, duplicated logic, leaky abstraction. Test that is flaky-prone (sleeps, real time, order-dependent).                                                                                                                                                                                                                                        | should-fix      | yes                |
| **low**      | Nice to have: naming, readability, small refactor, comment wording, a cheaper approach with no measurable impact. Never anything Prettier or ESLint owns.                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | nit             | no, listed only    |

Not a finding: style that tools own, preferences with no rule behind them, code the PR did not touch (unless the PR's change makes it wrong), and speculation with no concrete failure scenario.
